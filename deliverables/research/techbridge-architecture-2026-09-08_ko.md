> **가상 테스트 데이터 — 확정 계약 전 예비 아키텍처(indicative), 커밋된 범위 아님**

## 아키텍처 개요

관리형 대화형 AI 플랫폼(Managed Conversational AI) + 기존 CS 시스템 연동 구조. 벤더 락인을 피하기 위해 챗봇 엔진 계층을 추상화(어댑터 패턴)하여 특정 LLM 벤더 교체가 가능하도록 설계.

```
[웹/모바일 위젯] → [API 게이트웨이] → [대화 오케스트레이션 레이어]
                                          ├─ [시나리오 엔진: 주문/배송/반품]
                                          ├─ [LLM 어댑터 (교체 가능)]
                                          └─ [핸드오프 라우터] → [Zendesk API 연동]
                        [주문/배송 데이터] ←→ [사내 API (VPC 내부, 논리적 망분리)]
```

## 요구사항 → 아키텍처 요소 매핑 (추적성)

| 요구사항 ID | 아키텍처 요소 | 비고 |
|---|---|---|
| F1 | 임베드형 웹 위젯 (JS SDK) + API 게이트웨이 | 웹/모바일 WebView 공용 |
| F2 | 시나리오 엔진 (주문/배송/반품 3종 인텐트) | 사내 주문 API 직접 조회 |
| F3 | 핸드오프 라우터 | 신뢰도 임계값 미달 시 상담원 큐로 전환 |
| F4 | Zendesk API 연동 모듈 | 공식 REST API + Webhook, 커스텀 미들웨어 불필요 |
| N1 (3초 이내) | API 게이트웨이 캐싱 + 비동기 스트리밍 응답 | 부하 테스트로 검증 필요 (Phase 4) |
| N2 (망분리) | 사내 API를 VPC 내부에 배치, 챗봇 레이어는 VPC 외부 — API Gateway를 통한 논리적 망분리 | **가정**: 논리적 망분리로 충족 가능 — RFP의 미해결 질문(물리적 망분리 여부)에 따라 재설계 필요 |
| C1 (예산) | 관리형 서비스 우선 사용으로 인프라 자체 구축 비용 최소화 | 비용 산정에서 상세화 |
| C3 (벤더 락인 지양) | LLM 어댑터 패턴 — 엔진 교체 시 오케스트레이션 레이어 변경 불필요 | |

## 확장성 (성수기 대응, industry-expert 보강 반영)

오케스트레이션 레이어와 시나리오 엔진은 오토스케일링 구성 — 평시 대비 3배 트래픽(성수기)까지 수평 확장 가능한 구조로 설계.
